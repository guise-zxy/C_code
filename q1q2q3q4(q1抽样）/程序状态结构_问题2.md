# 问题2程序状态结构

## 1. 状态设计原则

程序状态必须只包含企业可观测信息和由可观测信息推导出的 belief。

不得包含：

```text
未经检测零件的真实质量标签；
程序直接偷看的隐藏质量状态；
未来随机结果。
```

隐藏质量状态只允许在概率转移和期望计算内部枚举，不能作为策略决策条件。

## 2. 推荐状态结构

建议使用如下结构：

```python
from dataclasses import dataclass
from typing import Literal

Belief = tuple[float, float, float, float]
# 顺序固定为：
# (1,1), (1,0), (0,1), (0,0)

Stage = Literal[
    "prepare_parts",
    "assemble",
    "final_inspection",
    "market",
    "returned",
    "rework_decision",
    "absorbed_success",
]

PartSource = Literal["new", "recovered"]
PartKnowledge = Literal["unknown", "known_good"]
FailureSource = Literal["none", "factory", "market"]

@dataclass(frozen=True)
class ProductionState:
    stage: Stage
    belief: Belief
    part1_source: PartSource
    part2_source: PartSource
    part1_knowledge: PartKnowledge
    part2_knowledge: PartKnowledge
    failure_source: FailureSource = "none"
```

## 3. 字段含义

### 3.1 stage

表示当前流程阶段：

```text
prepare_parts：准备零件，可选择检测或直接进入装配；
assemble：装配成品；
final_inspection：成品检测；
market：成品进入市场；
returned：市场退货；
rework_decision：对不合格成品选择拆解或报废；
absorbed_success：最终成功交付一件合格品。
```

### 3.2 belief

联合后验分布：

```text
(b11,b10,b01,b00)
```

顺序为：

```text
b11 = P(Z1=1,Z2=1 | 当前可观测历史)
b10 = P(Z1=1,Z2=0 | 当前可观测历史)
b01 = P(Z1=0,Z2=1 | 当前可观测历史)
b00 = P(Z1=0,Z2=0 | 当前可观测历史)
```

必须满足：

```text
b11 + b10 + b01 + b00 = 1
```

### 3.3 part_source

记录零件来源：

```text
new：新采购；
recovered：拆解回流。
```

### 3.4 part_knowledge

记录企业是否已经知道零件合格：

```text
unknown：质量未知，只能通过 belief 表示；
known_good：已通过准确检测确认合格。
```

当前建议正文主口径：

```text
known_good 回流件不复检。
```

每轮复检口径作为稳健性对照。

### 3.5 failure_source

记录不合格信息来源：

```text
none：当前无失败观测；
factory：成品检测发现不合格；
market：市场退货发现不合格。
```

该字段影响成本：

```text
market 失败需要计调换损失；
factory 失败不计调换损失。
```

## 4. 动作结构

建议动作结构：

```python
Action = Literal[
    "test_part1",
    "test_part2",
    "skip_part_tests",
    "replace_bad_part",
    "assemble",
    "test_final",
    "sell_without_final_test",
    "disassemble",
    "scrap_and_repurchase",
]
```

静态策略 `(d1,d2,df,dr)` 可以看作对这些动作的固定规则：

```text
d1=1：质量未知的零件1进入装配前检测；
d2=1：质量未知的零件2进入装配前检测；
df=1：装配后检测成品；
dr=1：发现不合格成品后拆解，否则报废重购。
```

## 5. 转移输出结构

每个状态和动作应返回一组可能转移：

```python
@dataclass(frozen=True)
class Transition:
    probability: float
    next_state: ProductionState | Literal["absorbed_success"]
    cost: float
    revenue: float = 0.0
```

要求：

```text
同一状态动作下，所有 transition 的 probability 之和为 1；
成本在转移时即时计入；
售价只在 absorbed_success 时计入一次。
```

## 6. 不可行判定

对固定策略或动态策略，都应构造非吸收状态转移矩阵 `Q`。

若存在以下情况，则策略不可行：

```text
1. 最终到达 absorbed_success 的概率小于 1；
2. 期望成本为无穷；
3. 存在无法退出的失败闭环。
```

不得使用最大循环次数截断后计算有限成本。

## 7. 与当前代码的关系

当前静态递归基线为了简化，把 `stage` 折叠进函数流程中，主要显式状态是：

```python
state = "START"
或
state = belief tuple
```

当前代码文件：

```text
problem_b/code/q2_static_enumeration.py
```

主要对应关系：

```text
belief tuple                 对应 ProductionState.belief；
"START"                      对应重新采购后的 prepare_parts；
expand_state(...)            对应从当前状态展开所有可能转移；
build_chain(...)             对应构造非吸收状态转移图；
evaluate_strategy(...)       对应求解吸收前期望成本和成功概率。
```

若后续实现完整动态策略，应将当前折叠状态扩展为 `ProductionState`，并让策略只能读取 `ProductionState` 中的可观测字段和 belief。
