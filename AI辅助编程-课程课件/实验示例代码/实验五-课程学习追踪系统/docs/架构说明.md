# 课程学习追踪系统 · 系统架构说明

## 1. 系统目标
帮助学生登记课程、记录每次学习时长、自动计算学习进度、生成统计报表与“需要学习”的提醒。

## 2. 总体架构（分层）

```
┌───────────────────────────────────────────────┐
│  前端（浏览器）  static/index.html + app.js     │
│  原生 HTML/CSS/JS，通过 fetch 调用 REST API     │
└───────────────────────────────┬───────────────┘
                                 │ HTTP / JSON
┌───────────────────────────────▼───────────────┐
│  HTTP 层  app.py                                │
│  路由分发、参数解析、错误码、静态文件服务        │
└───────────────────────────────┬───────────────┘
                                 │ 函数调用
┌───────────────────────────────▼───────────────┐
│  业务逻辑层  tracker_service.py (TrackerStore)  │
│  校验、进度/统计/提醒计算，与框架解耦            │
└───────────────────────────────┬───────────────┘
                                 │ SQL
┌───────────────────────────────▼───────────────┐
│  数据层  SQLite（courses / records 两张表）     │
└───────────────────────────────────────────────┘
```

**设计原则**：业务逻辑与 Web 框架解耦，使核心逻辑可独立单元测试，并便于将 HTTP 层替换为 Flask/FastAPI。

## 3. 数据模型

| 表 | 字段 | 说明 |
|----|------|------|
| courses | id, name, target_hours, created_at | 课程与目标学时 |
| records | id, course_id(FK), minutes, note, study_date | 每次学习记录 |

`records.course_id` 外键级联删除：删除课程时其学习记录一并删除。

## 4. 关键计算
- **学习进度** = min(100, 累计学习小时 / 目标学时 × 100%)
- **累计学习小时** = SUM(records.minutes) / 60
- **提醒规则**：未达标 且（从未学习 或 距上次学习 ≥ 阈值天数）

## 5. REST API 一览

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/courses | 课程列表（含进度） |
| POST | /api/courses | 新增课程 |
| DELETE | /api/courses/{id} | 删除课程（级联） |
| GET | /api/courses/{id}/records | 学习记录 |
| POST | /api/courses/{id}/records | 记录学习 |
| GET | /api/stats | 总体统计 |
| GET | /api/reminders | 学习提醒 |

## 6. 可扩展方向（供综合项目深化）
- 用户登录与多用户隔离；学习目标的周/月维度统计与可视化图表。
- 导出报表（CSV/PDF）；与日历/通知集成实现真正的定时提醒。
- 将 SQLite 替换为 PostgreSQL；将 HTTP 层迁移到 Flask/FastAPI。
