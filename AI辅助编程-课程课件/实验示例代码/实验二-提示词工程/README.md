# 实验二 · 示例代码：提示词工程实战与代码生成调优

围绕同一个基准任务（学生排序），演示三种提示技术的对比、参考实现、客观评测与优化日志。

## 基准任务
对学生列表按 **score 降序**、score 相同按 **name 升序** 排序；要求**稳定、不修改原列表**、含类型注解与边界处理。

## 文件清单

| 文件/目录 | 说明 |
|-----------|------|
| `prompts/01_zero_shot.md` | 提示词 A：零样本 |
| `prompts/02_few_shot.md` | 提示词 B：少样本（给示例） |
| `prompts/03_cot_rctf.md` | 提示词 C：四要素 + 链式推理（得到参考实现） |
| `sort_students.py` | 高质量**参考实现** |
| `test_sort_students.py` | 单元测试（功能正确性依据） |
| `evaluate.py` | 一键评测“功能正确性”得分 |
| `评估量表与优化日志.md` | 质量评估量表 + 提示词优化日志（示例 + 模板） |

## 怎么做这个实验

```bash
# 1) 阅读 prompts/ 下三种提示词，分别在 AI 工具中运行，保存各自生成的实现
# 2) 用本目录测试与评测脚本客观比较“功能正确性”
python3 -m unittest test_sort_students -v
python3 evaluate.py

# 3) 用《评估量表与优化日志.md》对多轮结果打分、记录迭代过程
python3 sort_students.py   # 查看参考实现的运行效果
```

## 学习要点
- 体会“同一任务、不同提示”对结果质量的巨大影响。
- 把“想法”翻译成**可验证的规格**：明确平分规则、是否可变、边界与异常。
- 用**客观评测 + 优化日志**把提示能力沉淀为可复用资产。
